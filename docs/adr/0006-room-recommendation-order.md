# ADR-0006. Порядок рекомендации номеров

## Контекст

Нужно равномерно распределять загрузку номеров и выдавать детерминированный порядок рекомендаций, в том числе для
автоподбора (`autoSelect=true`).

## Решение

`GET /api/rooms/recommend` возвращает те же свободные номера, что `GET /api/rooms` (`available = true`, нет удержаний
`HELD`, пересекающих период), по `times_booked ASC, id ASC`. `times_booked` растёт при confirm и уменьшается при release
(не ниже 0): счётчик отражает действующие бронирования, а не число попыток. `booking-service` не полагается на порядок
ответа и сам сортирует список по `timesBooked asc, id asc` (`RoomRanking`) — одинаково для `GET /booking/recommendations`
и автоподбора; сага пробует номера в этом порядке и при `409` переходит к следующему.

## Последствия

- Наименее загруженные номера первыми, равные — по `id`; результат не зависит от порядка ответа hotel-service
  (`BookingSagaTest.createBooking_autoSelectPicksLeastBookedRoomWithLowestId_whenHotelReturnsRoomsOutOfOrder`).
- Отменённое или компенсированное бронирование не увеличивает `times_booked`.
- Счётчик не учитывает длительность и цену; ночи считает статистика `/stats`.
- Номер, проигравший гонку, не ломает автоподбор: берётся следующий кандидат.
